## 초안을 만든 방법
워크플로 한 번(에이전트 10개): 사실 조사(약관용·처리방침용) + 법 요건 조사 → 두 문서 작성 → 3방향 검토(사실 일치 · 법적 위험 · 쉬운 말) → 검토 반영. 근거가 없는 정책은 지어내지 않고 `[운영자가 정할 것: …]` 로 남겼고, 명세에는 있지만 데모에 없는 장치는 `[서버 계획 — 출시 때 확인]`, 흔한 문장이지만 결정이 없는 것은 `[제안]` 이다. 법 조문은 일부만 원문과 대조했다(대조 못 한 곳은 '확인 필요').

## 검토 카드
- 탭 셋: **정할 것**(채울 값 3 · 출시 전에 꼭 9 · 약관 내용 37 · 처리방침 내용 10) · **이용약관**(41 — 조마다 '좋음 / 고칠 곳 있음' + 메모) · **처리방침**(22).
- 답은 아티팩트 db 컬렉션 `answers` 에 문서 하나씩 쌓인다 — 질문은 id 그대로(`F1`·`B3`·`T15`·`P4`·`Z1`), 조는 `tos-03`·`pv-14`·`tos-add`·`pv-head`. 질문 문서에는 고른 보기의 글(`chosen`)·칸 값(`fields`)·메모(`memo`)가, 조 문서에는 `verdict`(good·fix)·`memo` 가 있다. 읽기: `Artifact` list 에서 제목으로 찾고 → `ArtifactData` list.
- ⚠️ F1·F2 에는 실제 회사 정보·보호책임자 연락처가 들어온다 — **이 레포(공개)에는 옮기지 말 것**. 게시용 문서와 서버 설정에만 쓴다.
- 질문이나 틀을 고쳤으면 `node docs/legal/review-card/build.mjs <레포 밖 경로>.html` 로 다시 만들고 같은 아티팩트 주소로 다시 올린다(레포 루트가 그대로 배포되므로 만든 HTML 을 레포에 두지 않는다). 질문 id·보기 순서를 바꾸면 이미 받은 답이 엉뚱한 보기를 가리키니, 보기는 **뒤에만 더한다**.
