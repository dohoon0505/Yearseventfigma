## 질문별 정리

### 1. 연동 단가 — 면세 계산서 1건 값 · 부가세 포함 여부

- **회신이 말한 사실**
  - 연동 단가는 바로빌 개발자센터에 로그인한 뒤 **콘솔 › '인증키 및 제휴정보'** 에서 볼 수 있다.
  - 전자계산서는 과세든 면세든 **발행 1건에 110원이고, 부가세가 포함된 값**이다.
  - 수정 발행도, 일반 발행도 같은 값이다. 정발행·역발행·위수탁발행·수정발행을 모두 제공하고 단가가 같다.
  - API 로 낸 계산서의 내역을 조회하는 데는 요금이 붙지 않는다.
- **우리 설계에 주는 뜻**
  - 면세 계산서의 값이 따로 없다 — 1건 110원(부가세 포함)으로 본다. 우리가 내는 것은 정발행 한 가지다(공급자 = 운영사 · 청구 — BB2).
  - 2026-10-29 조사 때 본 사이트 일반 요금(1건 200원 + 충전 때 부가세 → 약 220원)의 절반이다(충전 결제 때 부가세가 더 붙는지는 아래 '답 없음').
  - 수정계산서(운영이 바로빌 웹에서 직접 낸다 — 명세 9.1 '수정·취소')도 한 장에 같은 값이다. 기재사항 착오정정처럼 두 장이 나가면 두 장 값이다(추정 — 220원).
- **답 없음**
  - 사용량에 따라 값이 달라지는지(조사 때 본 '표준형 · 구간별 차등'). 회신은 한 값만 적었다 — 우리 계정에 실제로 걸리는 값은 콘솔에서 확인한다(아래 '운영자가 할 일').
  - 운영이 바로빌 **웹(사이트)** 에서 직접 내는 수정계산서·수기 발급에도 이 연동 단가가 걸리는지. 회신은 API 단가를 말했다.
  - 충전(결제) 때 부가세가 더 붙는지 — 조사 때 본 파트너 약관 제11조는 결제금액에 부가세를 더해 청구한다고 적었다(`q38-2026-10-29.md`). 1건이 실제로 110원인지 121원인지는 콘솔 결제 화면에서 확인한다(아래 '운영자가 할 일' 2).

### 2. 단가 밖 비용 — 월 기본료 · 최소 사용료 · 최소 계약 기간 · 수정계산서 요금

- **회신이 말한 사실**
  - **선불 충전** 방식이다. 충전한 포인트에서 서비스마다 정해진 단가가 빠진다.
  - 바로빌에 저장된 내역을 조회해도 요금이 없다. 호출 건수·조회 건수·개발비·최저 사용 기준 같은 **따로 붙는 비용이 없다.**
  - 바로빌에 저장된 내역은 **파트너가 주기적으로 불러 가는 방식(폴링)** 이다.
  - 남은 포인트는 환불할 수 있다(바로빌 사이트 › 이용약관).
  - 수정계산서 요금은 1번 답에 있다 — 1건과 같은 값.
- **우리 설계에 주는 뜻**
  - 최저 사용 기준·개발비 같은 따로 붙는 돈이 없다고 했으니 쓴 만큼 낸다고 본다(월 기본료는 이름으로 답하지 않았다 — 콘솔에서 확인). 충전은 BB5 대로 운영이 모자랄 때마다 한다.
  - 회신은 '파트너가 주기적으로 불러 가는 폴링 방식' 이라고 했다 — 상태가 바뀌었다고 바로빌이 먼저 알려 주는 장치(콜백)는 따로 말하지 않았고 공개 문서에도 없어 없는 것으로 본다(추론). 우리 서버가 주기적으로 조회해야 한다. 그 조회에 돈이 들지 않으니, 명세 9.1 '국세청 전송' 행의 제안(전송이 끝나지 않은 계산서를 하루 몇 번 묶어 조회)을 요금 때문에 줄일 까닭이 없다. 조회 횟수는 그대로 서버 설계 때 정한다(운영자 확인 대기 — HANDOFF 2026-10-30 구간 ①).
- **답 없음**
  - '월 기본료' 와 '최소 계약 기간' 을 이름으로 답하지 않았다. 다만 '따로 붙는 비용이 없다' 고 했고, 3번에서 연동 계약 자체가 필수가 아니라고 했다.
  - 환불할 때 떼는 몫. 2026-10-29 조사 때 본 일반 이용약관(2025-06-04 적용)은 '대체로 10% 를 떼고 · 1,000원 이하면 돌려주지 않고 · 탈퇴하면 사라진다' 고 정한다. 이것이 연동 회원에게도 그대로인지는 회신이 '이용약관 참고' 라고만 했다.

### 3. 장애 때 보상 · 가용률 약속

- **회신이 말한 사실**
  - API 연동에 따로 계약을 맺는 것은 **필수가 아니다.** 파트너가 요청하면 **전자계약**을 한다.
  - 그 계약서에는 서비스 장애에 따른 손해배상과 면책이 적혀 있다.
  - **SLA(서비스 수준 약속)는 없다.** 가용률 보장도, 장애 시간에 따라 이용료를 깎아 주는 보상 기준도 적용되지 않는다.
  - 손해배상·면책은 바로빌 이용약관 **제9장 '손해배상 등'** 에서도 볼 수 있다(https://www.barobill.co.kr/join/barobill_rule.asp).
- **우리 설계에 주는 뜻**
  - 바로빌 장애로 생기는 손해(예: 1~7일 그룹의 지연발급 가산세 — 2026-10-23 결정 '작성일자 말일 그대로 + 가산세 감수')를 바로빌에게서 돌려받는 것을 전제로 하지 않는다. 대비는 지금 설계 그대로다 — 같은 관리번호로 다시 시도 · 마감일 첫 실패 알림(BB7) · 바로빌 웹 수기 발급(명세 9.1 '실패'·'폴백').
  - 계약서는 필수가 아니지만, 개인정보 처리를 맡기는 일은 문서로 정해야 하므로 전자계약을 요청한다(아래 '운영자가 할 일' 3).
- **답 없음**
  - 전자계약서의 손해배상 범위·상한(계약서 견본을 보지 못했다).
  - 그 계약서에 개인정보 위탁 조항(맡긴 일 밖에 쓰지 않음 · 안전조치 · 파기)이 있는지 — 묻지 않았다.

- **회신이 말한 사실**
  - ① **업무시간 밖 연락**: 평일 업무시간(09:00~18:00) 밖에 계산서 발급 장애가 나면 **바로빌 사이트 › 고객센터 › 1:1 문의하기** 나 **바로빌 개발자센터 › 문의하기** 로 접수한다. 접수된 문의는 장애 원인과 서비스 상태를 확인해 안내한다.

- **우리 설계에 주는 뜻**
  - 업무시간 밖에는 **글로 접수하는 길뿐**이다 — 회신은 전화 창구도, 답이 오는 시간도 말하지 않았다. 그래서 마감일 밤 장애는 바로빌 답을 기다리기 어렵다. 10일·28일이 토·일·공휴일이면 13:00 발급도 업무시간 밖이라 그날은 글 접수뿐이다(추론). 우리 몫은 BB7 의 첫 실패 알림과 수기 폴백이다(전체 장애면 바로빌 웹도 함께 막힐 수 있다 — 추론).

  - 점검은 금요일 22:00 에 시작해, 우리 몰림(10일·28일 13:00 자동 동의 직후 발급)보다 9시간 뒤다. 2026-10-29 조사한 2026년 공지에는 **둘째 주 금요일** 점검도 있었다(2/13 · 3/13) — 회신의 '보통' · '고정 아님' 과 맞는다. 그래서 **10일·28일이 금요일인 달**(다음은 2027년 5월 28일 · 9월 10일 · 12월 10일)은 그날 밤이 점검일 수 있고, 13:00 발급이 실패하면 고칠 시간이 22:00 까지로 준다(추론 — 그 달 공지를 본다).
- **답 없음**
  - 업무시간 밖 문의에 답이 오는 시간, 복구 목표 시간.
  - 정기점검을 10일·28일 낮에 피한다는 약속(회신은 '보통 금요일 22:00' 까지만 말했다).
  - 긴급 점검·장애 공지가 얼마나 빨리(미리) 오는지 — 알리는 길은 파트너 이메일·공지사항이라고 했다(4-②). 2026-07 클라우드 이전 때는 당일 공지였다.

### 6. 승인번호 — 생기는 때와 모양

- **회신이 말한 사실**
  - 계산서는 **발급하는 즉시** 국세청 승인번호가 매겨진다. 국세청에 보냈는지와 **관계없다.**
  - 그래서 '발급 즉시 전송' 설정이든 아니든, 발급이 끝난 뒤 `GetTaxInvoiceStateEX` 로 승인번호를 볼 수 있다.
  - 칸 이름은 **`NTSSendKey`**, 모양은 **24자리 문자열 · 하이픈 없음** 이다.
  - 다만 승인번호가 생겼다고 **국세청 전송까지 끝난 것은 아니다.** 전송이 끝났는지는 따로 전송 상태값으로 확인해야 한다.
- **우리 설계에 주는 뜻**
  - 명세 9.1 '응답' 확정: 발급완료(`BarobillState=3014`)를 확인한 **같은 조회**에서 승인번호를 받아 T6 을 보낸다. 예전의 '승인번호가 늦게 채워지면 T6 을 미룰지 운영자에게 묻는다' 갈래는 필요 없어졌다.
  - 국세청 전송 상태(`NTSSendState`)는 명세 9.1 '국세청 전송' 행대로 따로 본다 — `ISSUED` 판정은 전송 결과를 기다리지 않는다(지금 설계 그대로).
  - 수기 입력(명세 6.6 `mode=manual`) 형식 확정: **24자리 · 하이픈 없음.** 사람이 화면 표기대로 하이픈·공백을 넣어 적어도 걷어 낸 뒤 검사하고, 걷어 낸 값을 저장한다(T6 에 두 모양이 섞이지 않게). 예전 데모 예시 꼴 `YYYYMMDD-8자리-8자리`(하이픈 넣어 26자)는 버린다 — 프런트 검사식은 코드 담당이 고친다(HANDOFF 2026-10-31 구간).
- **답 없음**
  - 24자리가 숫자만인지(회신은 '24자리 문자열' 이라고만 했다) — 개발 때 테스트 발급 응답으로 본다.
  - 테스트 환경에서도 승인번호가 만들어지는지(문의 글에서 뺐다 — 개발 때 테스트 서버로).

### 7. 응답을 못 받은 발급 — 실제로 났을 수 있나 · 같은 관리번호로 다시 부르면

- **회신이 말한 사실**
  - `RegistAndIssueTaxInvoice` 를 부른 뒤 **시간 초과로 응답을 못 받거나 `-10000` 이 와도, 실제로는 발급됐을 수 있다.**
  - 그때는 반드시 **처음 관리번호(`MgtKey`)로 `GetTaxInvoiceStateEX` 를 먼저 조회**한다.
  - 발급 내역이 있으면 → 이미 발급된 것이니 다시 요청하지 않는다.
  - 발급 내역이 없으면 → **새 관리번호를 만들지 말고**, 처음 요청에 쓴 **같은 관리번호로** 다시 요청한다.
  - 이미 발급된 관리번호로 다시 요청하면 바로빌이 **중복 오류**를 돌려주므로, 같은 관리번호로 두 장이 나가지 않는다.
- **우리 설계에 주는 뜻**
  - 명세 9.1 '실패' 행의 설계 — 같은 정산은 늘 같은 관리번호(= 정산 `id`, 명세 5.4)로만 부르고, 다시 부르기 전에 상태를 먼저 조회한다 — 가 **바로빌이 권하는 절차와 같다.** 시간 초과·`-10000` 을 '다시 보내도 되는 것' 으로 두되 매번 조회부터 하는 설계도 확인됐다. 관리번호가 정산마다 고정이라 새 번호를 만들 일이 없다.
  - 발급 즉시 전송(BB3)이라 두 장이 나가면 취소할 수 없는데, 이 장치가 그것을 막는다는 판단도 확인됐다.
- **답 없음**(모두 개발 때 — 테스트 서버·바로빌 기술문의)
  - 중복 오류의 코드 번호(`-11024` · `-11013` · `-26000` 가운데 무엇인지).
  - 없는 관리번호를 조회하면 무엇이 오는지. 저장만 되고 발급이 안 된 임시저장(1000) 상태가 남는지.
  - 다시 보낼 간격·횟수, 시간 초과 권장 값, 그 밖에 다시 보내도 되는 오류 목록.

## 운영자가 할 일

1. **개발자센터에 파트너 이메일을 등록한다** — 장애·점검 공지 메일이 이 주소로만 온다(4번). 운영 담당이 매일 보는 주소로 둔다. 공지사항(바로빌 사이트·개발자센터)도 함께 본다.
2. **콘솔에서 단가를 확인한다** — 개발자센터 로그인 › 콘솔 › '인증키 및 제휴정보'. 우리 계정에도 1건 110원(부가세 포함)이 걸리는지, 충전 결제 때 부가세가 더 붙는지 본다(1번).
3. **전자계약을 요청한다** — 연동 계약은 필수가 아니지만, 요청하면 바로빌이 전자계약을 한다(3번). 우리는 거래처 정산·회계 담당자 이름 같은 개인정보를 바로빌에 맡기므로, 맡기는 일을 **문서로** 정해야 한다(개인정보 보호법 제26조 제1항 — 처리방침 초안 제10조가 인용한 조문). 계약서를 받으면 확인한다:
   - 위탁 조항 — 맡긴 일 밖에 쓰지 않음 · 안전조치 · 파기(언제 · 어떻게 — 회신은 '최대 5년 보관').
   - 다시 맡기는 곳(AWS — 5번)이 적혀 있는지(같은 법 제26조의 재위탁 항은 처리방침 초안이 '확인 필요' 로 둔 곳이다).
   - 손해배상·면책 범위(3번).
   - 계약서에 위탁 조항이 없으면 위탁 계약서를 따로 맺자고 요청한다. 국내 처리 확인 문서(5번 — 답 없음)를 이때 다시 요청할지는 운영자가 정한다.
4. **회신 메일을 남겨 둔다** — 처리방침에 '바로빌은 AWS 서울 리전에서 처리·보관 · 최대 5년 보관' 을 적는 근거다(국외 이전 없음이라고 단정하는 근거는 아니다 — 5번 '답 없음').
5. **그대로 남은 일**(2026-10-30 BB3 — 바뀌지 않음): 바로빌 웹 '국세청 전송설정' 에서 면세 '발급 즉시 전송' 과 '면세 지연발급 허용' 을 켠다(테스트·운영 따로).
6. 업무시간 밖 장애 연락 길을 운영 수칙에 적어 둔다 — 바로빌 사이트 › 고객센터 › 1:1 문의하기 · 바로빌 개발자센터 › 문의하기(4번). 전화 창구는 회신에 없다.
